# Weekly start/sit model — candidate covariates

Generated by `npm run test:covariates` (`scripts/test-weekly-covariates.ts`) — offline, from the committed snapshot `reports/2026-08-20/brier-prospective.json.gz`.

Rows: **3573** prospective player-weeks, 2025 season, input fingerprint `bba1d103`.

## What had to be true for a variable to ship

1. **Built only from earlier weeks.** A feature computed over the whole season
   would score week 3 using week 11's outcome. Rows without history (week 1, and
   any player's first appearance) are dropped from BOTH models, so the baseline is
   not handed an easier problem either.
2. **A nested likelihood-ratio test** against the shipped one-variable model, on
   the same rows with the same ridge penalty. One extra parameter, so
   LR ~ chi-square(1).
3. **Holm–Bonferroni across all 20 tests.** Four positions times five
   candidates. Quoting the smallest raw p-value here would be the multiple-
   comparisons error, and it is exactly how a spurious predictor gets shipped.
4. **And then out-of-sample.** Leave-one-week-out Brier must IMPROVE. A
   coefficient can be significant and still make next week's forecast worse:
   in-sample fit and out-of-fold accuracy are different questions.

## Can this harness detect anything at all?

Twenty tests coming back "not significant" is also exactly what a broken
likelihood-ratio computation looks like from the outside. So a positive control
runs first at every position: a feature built from the row's own outcome, which
is leakage by construction and can never ship. It must come back overwhelming or
the harness refuses to write this file.

## Result

**Nothing ships.** No candidate cleared both gates, so the model stays one
variable wide. That is the finding, not a failure to find one — and it is worth
more than a marginal second coefficient would have been, because it says the
projection is already carrying the information these candidates encode.

## What each candidate was, and why it was worth testing

- **prior hit rate** (`priorHitRate`) — share of this player's PREVIOUS weeks in which they cleared the line, shrunk toward the position base rate by 3 pseudo-weeks. Tests whether some players clear their line more reliably than their projection alone implies.
- **prior mean residual** (`priorMeanResidual`) — mean of (actual − projection) over this player's previous weeks. Tests whether the projection source is biased for particular players — if it is, the bias is knowable before kickoff and the model should use it.
- **prior availability** (`priorPlayedRate`) — share of this player's previous weeks in which they actually played. The fit scores a did-not-play as a failure, so a player who misses games should clear the line less often at the same projection.
- **week number** (`weekIndex`) — the week itself, centred. Tests whether the projection → outcome mapping drifts across a season (early-season projections being less informed).
- **log projection** (`logProjection`) — log(1 + projection) alongside the linear term. Not a new input — a functional-form test of whether the log-odds are really linear in points.

## Limits of this analysis

- **One season.** Everything here is 2025. A candidate that survives on one
  season of one scoring format is not established; it is un-refuted.
- **The baseline is re-fitted on the history-only subset**, so the Brier figures
  in this table are not directly comparable to the numbers in
  `docs/brier-results.md`, which use every row. Comparisons WITHIN this table are
  valid because both arms see identical rows.
- **Leave-one-week-out is not a true holdout.** It reuses the same season, and
  protocol 6 in `docs/` already measured that it is mildly optimistic.
- **No IDP, no kickers.** The shipped model covers QB/RB/WR/TE only, and so does
  this.
