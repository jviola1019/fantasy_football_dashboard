### Kickers and team defences are NOT in this bundle


This file has no `K` rows and no kicking columns, and team defences are not player rows at all — so nothing here can model them. That is a fact about THIS BUNDLE and it was once reported as though it were a fact about the data that exists, which was wrong: nflverse publishes `player_stats_kicking_<season>.csv`, `stats_team_week_<season>.csv` and the final scores needed for points allowed. `npm run acquire:kdst` fetches eight seasons of all three in 70 KB, and `npm run holdout:kdst` models them. "Not in the file I already had" is a different claim from "does not exist", and only one of them was checked.

## 3. The 2025 weekly snapshot (what the SHIPPED model was fitted on)


- Season: **2025**
- Prospective rows: **3573** of 3573 total
- Weeks: **17** (1–17)
- Duplicate (player, week): **0**
- Fields present: kind, player_id, position, week, proj_pts_ppr, actual_pts_ppr, played


**This is the constraint that shapes every weekly-model result in this repo.** The snapshot carries a projection and an outcome and nothing else — no usage, no opponent, no injury designation. The shipped model can only be tested against features derivable from those columns, which is why `docs/model-gauntlet.md` searched 44 history-derived covariates and found nothing: there was nothing else in the file to find.


The nflverse rows audited in section 1 carry the usage columns AND their own `fantasy_points_ppr` outcome, so they support a weekly model in their own right — and, spanning 2017–2024, they support a **held-out-season** evaluation that the single-season 2025 snapshot cannot. That is what `scripts/holdout-weekly-gauntlet.ts` does. What they do NOT carry is the FantasyPros projection, so they cannot test the shipped model's own predictor — a different question from whether usage predicts weekly outcomes at all.
