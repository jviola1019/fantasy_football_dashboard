# Current-build viewport evidence

Every file in this directory is **regenerated by `npm run e2e`** and describes
whatever build last ran the suite. Treat it as "the current UI", never as a
record of a particular date.

It exists because the alternative was worse. `e2e/21-waiver-notice-viewports.spec.ts`
wrote its mobile/tablet/desktop captures straight into `reports/2026-08-20/screens/`,
so every e2e run after that audit overwrote the audit's own evidence with the
current build. A dated report that silently updates itself is not evidence, and
nothing about the arrangement announced itself — the files simply changed under a
heading that claimed a date. Found 2026-09-01 when an unrelated run left those
three PNGs modified in `git status`.

**If a dated report needs a frozen capture, copy the file into that report's own
directory in the same commit.** Anything left here will be overwritten by the
next run.
