# `reports/` — what belongs here, and what does not

Two kinds of thing live here, and the distinction is the whole point of this
file.

## 1. Dated session reports — `reports/YYYY-MM-DD/`

One directory per working session, holding the write-up and any **frozen
evidence** that write-up depends on: a committed data snapshot, a protocol fixed
before scoring, a measurement that cannot be reproduced later because the
upstream data has moved on.

These are the record. They are read, cited by `docs/` and by commit messages,
and they do not get regenerated — a dated report that changes is not a record.

| directory | what it holds |
|---|---|
| `2026-08-06/` | forensic audit and remediation |
| `2026-08-20/` | the frozen holdout protocols (1–7), the nflverse bundle, the prospective Brier snapshot — the largest directory, and the one everything statistical depends on |
| `2026-08-25/`, `2026-08-26/`, `2026-08-28/` | audit and design-gate sessions |
| `2026-09-01/` | S5–S8: chart kit, hierarchy, the calibrated model, the landing page |
| `audit-2026-06-09/` | an external audit and its reconciliation |
| `screens/` | current-build viewport captures, **gitignored** — regenerated by every `npm run e2e` |

## 2. Loose audit reports at the root

`audit-*.md`, `final-audit-report.md`, `opus48-reverification.md`. These predate
the dated convention. They are findings ledgers, still cited, and they stay.

## What does NOT belong here

**Regenerable command output.** On 2026-09-02 this directory contained ten files
that were nothing but the stdout of a single run on 2026-05-30:

```
build.txt  tsc.txt  unit.txt  eslint.json  playwright.json
workflow-summary.json  design-tokens.json  brier-backtest{,-v2,-prospective}.txt
```

They were removed, and it is worth saying why rather than just tidying:

- **Stale and silently wrong.** `build.txt` reported Next.js 16.2.6 against a
  repo on 16.3.1. `tsc.txt` was zero bytes. Somebody reading either as evidence
  of the current state would have been misled, which is worse than having no
  file.
- **Unreferenced.** Nothing in `README.md`, `docs/`, `src/`, `scripts/`, `e2e/`,
  `HANDOFF.md` or `CLAUDE.md` linked to any of them.
- **Superseded.** The Brier dumps are console text; `docs/brier-results.md` is
  the generated, current, cited evidence, and `npm run brier:backtest`
  regenerates it.
- **They embedded absolute local paths** (`C:\Users\jviol\...`), which is a
  needless thing to commit.

If a gate's output is worth keeping, it belongs in a **dated report that
interprets it**, not as raw stdout at the root. `.gitignore` now blocks these
filenames so they cannot drift back in.

The rule, in one line: **a file here should be something a person wrote, or
something a person's writing depends on.**
